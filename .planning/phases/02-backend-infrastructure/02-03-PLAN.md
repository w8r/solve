Create production Dockerfile per RESEARCH.md code examples.

**Dockerfile (at project root):**
```dockerfile
# Multi-stage build for smaller production image
# Source: Docker + Node.js best practices 2026
FROM node:22-alpine AS builder

WORKDIR /app

# Copy package files for all workspaces
COPY package*.json ./
COPY packages/api/package.json ./packages/api/
COPY packages/common/package.json ./packages/common/

# Install all dependencies (including dev for build)
RUN npm ci --workspace=@solve/api --workspace=@solve/common

# Copy source code
COPY packages/api ./packages/api
COPY packages/common ./packages/common
COPY tsconfig.base.json ./

# Build TypeScript for both packages
RUN npm run build --workspace=@solve/common && npm run build --workspace=@solve/api

# Production image
FROM node:22-alpine

# Security: don't run as root
RUN addgroup -g 1001 -S nodejs && adduser -S nodejs -u 1001

WORKDIR /app

# Copy built artifacts
COPY --from=builder --chown=nodejs:nodejs /app/packages/api/dist ./packages/api/dist
COPY --from=builder --chown=nodejs:nodejs /app/packages/common/dist ./packages/common/dist

# Copy package files for production install
COPY --from=builder --chown=nodejs:nodejs /app/package*.json ./
COPY --from=builder --chown=nodejs:nodejs /app/packages/api/package.json ./packages/api/
COPY --from=builder --chown=nodejs:nodejs /app/packages/common/package.json ./packages/common/

# Install production dependencies only
RUN npm ci --omit=dev --workspace=@solve/api --workspace=@solve/common

# Switch to non-root user
USER nodejs

# Environment defaults (overridden by runtime env vars)
ENV NODE_ENV=production
ENV PORT=3000

# Expose port
EXPOSE 3000

# Health check (Docker native, not Fly.io specific)
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:3000/health || exit 1

# Start server (direct node for faster startup, not npm)
CMD ["node", "packages/api/dist/index.js"]
```

Create Fly.io deployment configuration per RESEARCH.md code examples.

**fly.toml (at project root):**
```toml
# Fly.io deployment configuration
# Docs: https://fly.io/docs/reference/configuration/
app = "solve-api"
primary_region = "sjc"  # San Jose - adjust based on user location

[build]
  dockerfile = "Dockerfile"

[env]
  NODE_ENV = "production"
  PORT = "3000"
  LOG_LEVEL = "info"
  # MONGODB_URI set via `flyctl secrets set` - never in config

[http_service]
  internal_port = 3000
  force_https = true
  auto_stop_machines = "stop"
  auto_start_machines = true
  min_machines_running = 0

  [[http_service.checks]]
    interval = "30s"
    timeout = "5s"
    grace_period = "10s"
    method = "GET"
    path = "/health"

[[vm]]
  size = "shared-cpu-1x"
  memory = "256mb"
```

Key decisions per CONTEXT.md:
- Fly.io with Docker (not Vercel Serverless)
- Zero vendor lock-in (standard Dockerfile runs anywhere)
- Free tier sufficient for prototype
- Health check on /health endpoint
- MONGODB_URI via secrets (never in config)
